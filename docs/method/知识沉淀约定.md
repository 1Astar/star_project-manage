# 知识沉淀约定

对应 Notion「个人产品经理工作台」中的 03 知识体系 / 04 方法论，以及 LLM Wiki 分层思路。

## 分层

| 层 | 放什么 | 对应用法 |
| --- | --- | --- |
| 原文层（raw） | 访谈原文、竞品截图、会议纪要原文、外部链接 | 调研条目、附件；不擅自改写 |
| 提炼层（wiki） | 决策结论、概念页、规则摘要、已答「为什么」 | 知识点、方法论、项目结论 |
| 热缓存（hot） | 当前会话/本周上下文摘要（约 500 字） | 下次开工不用重口述背景 |

## 可检索归档类型

- **实体：** 竞品、协议、模块名、系统组件
- **概念：** 交互模式、权限模型、状态机思路
- **问题：** 已答过的「为什么这么做 / 为什么不做」
- **方法论：** 可复用的做事方式（如本仓 PRD 五步法）

## 会话结束动作

1. 更新热缓存：本周在做什么、未决问题、负责人
2. 把新确认的结论写入提炼层，原文留在原文层
3. 定期 lint：孤立结论、过期主张、互相矛盾的规则、断链引用

## 与需求交付的关系

- 需求正式文档在「产品工作 / 正式目录」
- 草稿在「草稿箱」
- 调研与学习笔记不直接当 PRD；提炼后再进入规则清单

## 与 Star PM「资料 / 链接」的关系（已确认）

- **个人工作台**：正文（Wiki、笔记、方法论、模板、热缓存）
- **资料 / 链接**：外链指针 + 标签（`知识体系` / `方法论` / `模板` / `原文` / `竞品` / `Notion`）
- 外链只维护一份；正文需要时链回资料，资料不复制长文
