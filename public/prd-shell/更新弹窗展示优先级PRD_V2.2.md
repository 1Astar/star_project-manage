# 更新弹窗展示优先级 PRD

本期只编排 OS / 客户端两类原有更新弹窗的展示顺序。弹窗以单独弹窗盖在主屏幕上展示。本期不做胶囊、不做通知入口；原型属二期。

## 2. 背景

OS 与客户端各自检查更新、各自使用原有更新弹窗。两项同时有更新时，需确定弹窗顺序，以及 OS 流程结束后客户端弹窗的触发条件。

本期只改编排，不改原弹窗的内容、按钮与更新流程。

## 3. 目标

1. 客户端与 OS 同时有更新时：
    1. 先展示 OS 更新弹窗；
    2. OS 更新流程结束后（一般需重启），再展示客户端更新弹窗；
    3. 两个弹窗不重叠。
2. 版本检查与展示：
    1. 登录进入主屏幕后，自动检查当前是否有 OS／客户端更新；有更新则弹窗。
    2. 用户手动点击「检查更新」时，重新检查是否有 OS／客户端更新；有更新则弹窗。
3. 检测结果：
    1. 有更新：展示对应更新弹窗。
    2. 无更新：不弹该侧。
    3. 失败或超时：不弹该侧；两侧都没有可更新且至少一侧失败或超时 → 仅手动检查提示失败，登录检查不提示。

## 4. 核心功能

| 阶段 | OS 提醒 | 可选客户端更新提醒与入口 |
| --- | --- | --- |
| 本期 | 自动展示原更新弹窗 | OS 流程结束后自动展示原客户端更新弹窗 |
| 二期 | 保留原更新弹窗 | 通知提醒；点击后打开客户端更新弹窗（含交互原型） |
| 三期 | 设置内新增系统更新管理 | 通知点击进入 设置 → 更新 → 客户端更新 |

### 4.1 检测入口与首次弹窗

1. 检测时机
    1. 登录进入主屏幕，且当前可展示单独更新弹窗（主屏幕上无其它阻塞更新弹窗的全屏遮罩时）→ 检查 OS 与客户端更新。仅启动未登录不弹。
    2. 用户点击现有「检查更新」→ 重新检查 OS 与客户端更新。
2. 两项均进入终态（有更新／无更新／失败／超时）后，按本轮结果判定；不使用上一轮结果；不自动下载或安装。
3. 每次重新登录均重新检查。关闭弹窗不等于忽略版本；选择「忽略本次更新」后按原忽略规则过滤该版本。

### 4.2 检测结果与异常

1. 有更新：按 4.1／4.3 展示对应弹窗。
2. 无更新：不弹该侧。
3. 失败或超时：不弹该侧；超时写日志并回传后端；旧轮次超时结果不参与当前轮次判定。
4. 两侧都没有可更新，且至少一侧失败或超时：
    1. 登录检查：不提示。
    2. 手动检查：显示一次「检查更新失败，请稍后重试」（有现有载体用现有，否则居中 Toast）。
5. OS／客户端安装失败走原更新流程结果弹窗，不按检测失败处理。

### 4.3 两项更新的弹窗顺序与操作

两项均确认有更新时，先展示 OS 弹窗。OS 更新流程结束后（一般需重启；未重启时须 OS 弹窗及结果态均已关闭、主屏幕可再次展示单独弹窗），再展示本轮客户端原更新弹窗。两个弹窗不重叠。

| OS 流程状态 | 客户端弹窗处理 |
| --- | --- |
| 关闭 OS 更新弹窗 | 主屏幕可展示后自动展示 |
| 「忽略本次更新」 | 只忽略 OS；OS 退出后仍自动展示客户端弹窗 |
| 取消 OS 更新且原流程已退出 | 主屏幕可展示后自动展示 |
| OS 更新失败，结果弹窗仍在 | 等结果弹窗关闭后再展示客户端 |
| OS 更新成功（未重启） | 主屏幕可展示后自动展示 |
| 更新中／结果弹窗未关／设备重启 | 等待退出；重启则清除本轮待展示，重新登录后重检 |

- 「忽略本次更新」只作用于被操作的更新项。
- 历史版本下载入口：仅 Android 显示；iOS／Windows／macOS 隐藏且不留空位。
- 版本依赖：本期沿用各自现有可更新结果，不新增依赖判定（依赖见二期）。
- 强制更新：沿用原强制限制；本期不因编排改变强制行为。

### 4.4 本期逻辑状态

描述判定与续弹所需状态；不限定接口字段名或存储结构。

| 状态 | 类型与取值 | 初始值／为空时处理 |
| --- | --- | --- |
| 检查来源 | 枚举：登录进入主屏幕、手动检查 | 每轮必有；缺失则不触发展示判定 |
| 检查轮次 | 唯一轮次标识 | 登录或手动检查时生成；缺失或旧轮次结果不参与当前判定 |
| OS 检测结果 | 枚举：未返回、有更新、无更新、失败、超时 | 初始未返回；超时为终态，不视为无更新 |
| 客户端检测结果 | 同 OS | 初始未返回；非「有更新」时不进入客户端待展示 |
| 首次弹窗判定 | 枚举：未判定、不展示、OS 更新弹窗、客户端更新弹窗 | 两项终态后只判定一次 |
| OS 流程状态 | 枚举：未开始、展示中、更新中、结果待关闭、已结束、重启中 | 结果未关／更新中／重启时不进入客户端续弹 |
| 本轮客户端待处理 | 枚举：无、待处理、已展示、已完成 | 双项有更新时为待处理；可展示时弹一次；新轮次或重启清除 |

## 5. 交互流程

| 步骤 | 动作 | 结果 |
| --- | --- | --- |
| 1 | 登录主屏幕或手动「检查更新」 | 生成新轮次；只检查版本，不自动下载／安装 |
| 2 | OS／客户端均进入终态 | 按 4.2 表决定首次弹窗 |
| 3 | 仅一项有更新 | 打开该项原弹窗 |
| 4 | 两项均有更新 | 先 OS；OS 流程结束且可展示单独弹窗后，自动打开客户端原弹窗 |
| 5 | 客户端弹窗退出 | 本轮弹窗流程结束 |
| 6 | 重启，或再次「检查更新」 | 清除待展示；重启后下次登录重检；手动检查立即开新轮 |

## 7. 验收标准

| 场景 | 条件／操作 | 预期结果 |
| --- | --- | --- |
| 登录检查 | 登录进入主屏幕 | 检查两项；有更新按 4.1 首弹；无更新不弹；不自动下载／安装 |
| 单项／双项 | 仅 OS／仅客户端／双有／双无 | 按 4.2；双有时 OS 后客户端，不重叠 |
| 关闭／忽略 OS | 双项有更新 | OS 结束后自动出客户端；OS 忽略不替客户端忽略 |
| OS 失败／成功／重启 | 双项有更新 | 失败结果关闭后或成功未重启可展示后出客户端；结果未关或重启中不出；重启后重检 |
| 一侧有更新、一侧失败／超时 | 另一侧无更新或不影响 | 只弹有更新那一侧；失败／超时不弹 |
| 两侧都无可更新且有失败／超时 | 登录 vs 手动检查 | 登录不提示；手动检查一次失败反馈 |
| 重新检查 | 前轮未结束时手动检查 | 废弃前轮待展示，只按新轮结果 |
| 通知消息 | 本轮有更新 | 不新增通知消息；不出现通知浮窗 |

原弹窗按钮、下载、安装、进度与强制更新限制仍按各自既有流程验收。

## 8. 二期：通知消息与更新依赖

二期将可选客户端更新改为通知提醒；点击后打开客户端更新弹窗。OS 仍自动展示原弹窗。双项有更新时：OS 流程退出且主屏幕可展示后，展示客户端通知，不再自动续弹客户端更新弹窗。

### 8.1 通知消息：内容与跳转

| 字段 | 类型／范围 | 默认 | 为空／非法时 |
| --- | --- | --- | --- |
| 适用对象 | 当前客户端可选更新 | 无 | 不匹配则不建通知；OS 更新不建通知；强制更新走原强制流程 |
| 消息类型 | 系统消息（system） | system | 非法则上报后端，不展示 |
| 图标色 | 成功绿 #079F4A（设计系统 Success） | #079F4A | 缺失用默认 Success 色 |
| 标题 | 固定文案「客户端有更新可用」；单行，超出省略 | 固定文案 | 缺失则上报后端，不展示 |
| 副标题·版本号 | 字符串，可识别版本 | 无 | 缺失或非法 → 上报后端，不展示该通知 |
| 副标题·安装包大小 | 字符串或字节数，可展示 | 无 | 缺失或非法 → 上报后端，不展示该通知 |
| 副标题·更新摘要 | 字符串 | 无 | 缺失或非法 → 上报后端，不展示该通知 |
| 发生时间 | 首次确认该可用版本的时间 | 确认时刻 | 同版本重检不改时间；被新版本替换时更新 |
| 数量与版本 | 每客户端一条最新可用版本 | 无 | 新版本替换旧消息，不累积历史 |
| 安装状态 | 以当前客户端已装版本为准 | 未安装该版本 | 其他设备已装不代表当前客户端已更新 |
| 点击目标 | 二期：客户端更新弹窗；三期：设置更新模块 | 弹窗 | — |
| 下载历史版本 | 仅 Android 显示入口 | 按平台 | 非 Android 隐藏且不留空位 |

副标题在列表完整展示；PC 右上角新消息浮窗最多 2 行。日期格式沿用通知消息 PRD。

### 8.2 通知消息：触发、展示与移除

1. 触发：登录主屏幕可展示时，或手动「检查更新」→ 重检。本轮确认客户端有可用更新且依赖已满足 → 新增或刷新最新版本消息。同轮最多浮出一次；同版本下次登录可再提醒，列表不叠重复条目。
2. 忽略：关闭浮窗或弹窗 ≠ 忽略版本；仅「忽略本次更新」按原规则过滤。
3. 失败／超时：不新增、不替换消息；未知结果不当作无更新。超时结果写日志回传后端。
4. 移除：当前客户端已安装该版本、版本撤回或过期 → 从通知列表删除该条，不展示「已失效」。徽标按列表剩余条数重算（减 1；减至 0 则隐藏）。用户删除通知只去入口，≠ 忽略版本。
5. 点击时二次校验（防列表未及时刷新）：
    1. 不覆盖的情况：新版本已确认且列表已替换为最新条目时，按新条目点击打开弹窗，不适用本条。
    2. 适用场景：列表仍挂着某版本消息，但点击瞬间该版本已不可用——例如已安装、被撤回／过期，或服务端已换更新版本而本地列表尚未刷新。
    3. 目标不可用：移除该条，徽标按剩余条数重算，提示「该更新已不可用，请重新检查」；不启动旧版下载。
    4. 二次校验失败：指点击时的网络／检查接口失败，不是「检测失败写进通知栏」。消息本就在列表中，提示「检查更新失败，请稍后重试」并保留该条供重试。检测失败／超时本身仍按上文：不新增、不替换消息。
6. PC／移动（摘要，细则以通知消息 PRD 为准）：
    1. 浮窗队列：PC 右上角新消息浮窗按事件发生时间正序入队，同一时间按接收序号；约每 300ms 展示一张；单张默认展示 4500ms，悬停暂停计时；关闭浮窗只收起当前提醒，不删除列表消息。
    2. 列表排序：通知列表按发生时间倒序。
    3. 徽标：PC 通知入口徽标为列表实际总数；1～99 显示数值，超过 99 显示「99+」，为 0 时隐藏。
    4. 移动端：独立全屏通知页；删除按钮常态显示；接近底部时每次最多追加 50 条。
    5. 点击：二期点客户端更新浮窗或列表消息一律打开客户端更新弹窗；其他通知仍按各自原规则。

### 8.3 依赖关系

未提供依赖信息 = 无依赖。已声明依赖时必须同时给出可识别依赖对象与最低版本；不完整、无法识别或无法启动的循环依赖 → 阻止相关更新并上报后端。

| 字段 | 类型／范围 | 默认 | 为空时处理 |
| --- | --- | --- | --- |
| 更新对象与适用端 | OS 或当前平台客户端 | 无 | 缺失／不匹配 → 不展示，上报后端 |
| 可用版本与安装包 | 有效版本与包信息 | 无 | 缺失／无效 → 按检测异常，不展示 |
| 依赖对象 | OS／客户端／无 | 无 | 未提供或为「无」→ 无依赖，不上报 |
| 最低依赖版本 | 可识别版本；无依赖时为空 | 空 | 声明依赖但缺最低版本 → 不完整，不展示并上报 |
| 是否强制 | 是／否 | 原流程判定 | 缺标记仍按原流程 |
| 有效截止时间 | 日期时间或空 | 空 | 空 = 不按时间过期；安装完成或撤回仍移除通知 |

| 依赖状态 | 展示 | 后续 |
| --- | --- | --- |
| 无依赖或已满足 | OS 有更新先 OS 弹窗；客户端走通知 | 双项时 OS 结束后出客户端通知 |
| 客户端依赖 OS | 先 OS 弹窗；暂不出客户端通知 | OS 成功且满足后再检并生成客户端通知 |
| OS 依赖客户端 | 先客户端通知→弹窗；OS 暂不弹 | 客户端成功后再检；仍需 OS 则出 OS 弹窗 |
| 依赖信息不完整／无效 | 不展示需该依赖的更新 | 上报后端 |
| 无法启动的循环依赖 | 两项均不展示、不安装 | 上报后端；仅一方已满足时不按循环阻断 |

服务端发布前校验；客户端仍校验。上报含更新对象、目标版本、当前 OS／客户端版本、平台、原因。可选依赖缺失按无依赖，不上报错误。

### 8.4 强制更新

1. OS 强制：沿用原限制；客户端不得覆盖未结束的 OS 强制流程。
2. 客户端强制：不降为可一直不点的通知；若依赖 OS，先满足 OS 再进原强制流程。
3. 双强制：先校验依赖；缺失／无效／循环 → 阻止并上报，不回退为忽略依赖的 OS 优先。
4. 强制更新失败属更新流程结果，不改写为检测失败。

| 场景 | 操作／条件 | 预期 |
| --- | --- | --- |
| 通知跳转 | 点浮窗或列表中的客户端更新消息 | 打开客户端更新弹窗，不进设置模块 |
| 副标题缺字段 | 版本号／包大小／摘要任一缺失或非法 | 上报后端，不展示该通知 |
| 重新登录 | 上次关提醒未更新 | 按二期再提醒；同版本复用条目 |
| 新版本 | 旧通知仍在时确认新版 | 替换为最新，旧版不再显示 |
| 移除 | 已安装／撤回／过期 | 列表删除该条；徽标按剩余条数重算，为 0 则隐藏 |

| 依赖异常 | 缺失／不完整／循环 | 阻止相关更新并上报 |
| 强制更新 | 客户端原为强制 | 仍走强制流程，不因通知绕过 |

### 8.6 二期逻辑状态

| 状态 | 类型与取值 | 初始／为空 |
| --- | --- | --- |
| 通知列表条目 | 无／当前最新可用版本 | 初始无；替换更新原条目；已装／撤回／过期移除 |
| 本轮浮窗状态 | 未提醒／已提醒／用户关闭／已点击 | 每轮未提醒；同轮不重复浮出 |
| 通知点击目标 | 客户端更新弹窗 | 二期固定；先校验可用性 |
| 依赖状态 | 无依赖／已满足／未满足／不完整／无效／循环 | 未提供依赖信息 = 无依赖 |
| 当前更新目标 | 无／OS／客户端 | 一流程未退出不叠加另一弹窗 |

## 9. 三期：设置中的独立更新模块

设置中新增独立「更新」模块，与系统信息页分开。三期通知点击定位到对应更新对象；二期仍打开原更新弹窗。

| 更新对象 | 入口 | 展示与操作 |
| --- | --- | --- |
| 系统更新 | 设置 → 更新 → 系统更新 | 当前／可用版本、更新内容、下载安装状态；忽略／立即更新等 |
| 客户端更新 | 设置 → 更新 → 客户端更新 | 当前／可用版本；历史版本仅 Android |

- 通知点击直达对象；进入后重新校验可用版本。
- 无可用更新时展示当前版本与检查入口；已装／撤回／过期不作为可更新项。
- 进度、失败反馈与强制限制适用于独立模块；不能靠关闭设置绕过强制更新。
