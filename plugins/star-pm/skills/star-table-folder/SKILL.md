# Star · 表格与文件夹通用能力

做 **项目库 / 需求池 / 灵感表 / 看板旁的表格 / 文件夹式树表** 时用本 skill。  
不适用于：Word/PPT 文档里的静态表（那走 `doc-delivery-formats` / `word-docx-professional`）。

## 硬规则：优先级

1. **最终以用户当时的要求为准。**  
   用户当场说「只要按更新时间排、先不要筛选」→ 按当场要求做，不必强行上齐本 skill 全套。
2. **用户没点名时**：按本 skill 的通用底线做，并在 PM Idea/需求里写清做到哪一档。
3. **禁止**用「skill 里写了所以必须一次做完」覆盖用户明确的缩小范围。

原文口径（用户）：「可以加到 skill 里做完通用要求，不过最终还是以我当时的要求为准。」

---

## 通用底线（默认应具备）

面向「像文件夹/表格」的数据列表（项目、需求、灵感、资源行等），**默认**具备：

| 能力 | 期望 |
|------|------|
| **排序** | 列头可排序；项目类列表至少支持 **按更新时间**（近→远为常用默认或一键切换） |
| **筛选** | 状态 / 优先级 / 关键字；复杂表可加负责人、板块等 |
| **移动** | 同级重排；能挂到另一父级（DnD 或菜单「移到…」） |
| **删除** | 单条 + 批量；有确认；树节点删除要说清是否含子树 |
| **父子 / 文件夹感** | 可挂父子；缩进或折叠；「文件夹」可以是 `type=folder/epic` 或 `parent_id` 树，不必单独实体，但交互要像文件夹 |

可选增强（用户要或表很重时再上）：列宽记忆、保存视图、批量改状态、导出。

## 与现状对齐（避免重复造轮）

| 面 | 已有 | 常见缺口 |
|----|------|----------|
| 项目需求池表 `requirement-pool-table` | 多级父子、列排序、筛选、DnD、批量删 | 抽成共用组件仍不足 |
| 项目库 `project-library-table` | 一层父子、DnD 顺序 | **默认不按更新时间**；筛选弱；无批量删 |
| 全局需求表 | 偏只读 | 缺树/排序/移动/删 |

新做表：**优先复用**需求池表的交互模式，再抽共用；不要每个页面各写一套半残表格。

## Agent 做事清单

1. 先问清（或从用户话里确认）：这张表要 **全套底线**，还是 **只要某几项**（如只按更新时间排）。
2. 写进 Star PM（Idea/需求），`relatedModule` 建议：`项目库·表格` / `需求任务·需求池` 等。
3. 实现时：有现成树表就扩展；没有再抽 `components/` 共用块（排序头、筛选条、行 DnD）。
4. 验收：按用户当场清单勾；skill 里没被点名的能力可记「后期」并用 `defer-scope-record` 写清。

## 不做（除非用户点名）

- 一次重写全站所有表
- 为「文件夹」强行新建独立 DB 表（有 `parent_id` / type 即可）
- 用 skill 否定用户当场的缩小范围
