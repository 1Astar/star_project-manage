# Verification Before Completion（Star）

在声称「做完了 / 已修复 / 已通过」之前执行。

## 硬规则

1. **对照初始要求**：用户原话与验收路径是否都覆盖？缺的标出来，不要静默当完成。
2. **跑证据**：相关命令 / 单测 / `tsc` / 主路径冒烟；把失败当未完成。
3. **全链路**：问题 → 方案假设 → 数据/状态 → 用户可感知结果；链路有洞先提醒。
4. **UI 改动**：至少走一遍用户路径（打开页面 → 关键操作 → 可见结果）。
5. 验证不过 → 先修再宣称；禁止用「我觉得没问题」代替验证。

## 收工与 PM

验证通过后再 `finish_change_session` / 勾完成；仍有未完成需求时写清并当面说「下一步接什么」（`star-pm-write-release`）。
