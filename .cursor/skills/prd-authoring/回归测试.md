# PRD Skill 回归测试 V2.0

以下为输入与预期行为，测试用例本身不代表实际产品需求。

| 编号 | 输入 | 预期 |
|---|---|---|
| 1 简单规则 | 同时存在 OS 和客户端更新，先展示 OS，完成后再检测客户端。 | 拆分规则；保留「再检测客户端」，不改成直接展示；不补充其他行为。 |
| 2 禁止虚构异常 | 登录桌面后自动检查更新，有更新则弹窗。 | 不自行增加超时、失败、重试或 Toast 规则。 |
| 3 版本变更 | 一期只调整两项更新弹窗的优先级。 | 只描述本期优先级变更，其他业务保持不变。 |
| 4 语义保持 | OS 流程结束后，重新检测客户端更新。 | 不得改成被动触发或直接展示客户端弹窗。 |
| 5 被动触发 | OS 弹窗关闭后，被动触发展示规则，使用已有客户端检测结果。 | 不得改成主动重新检测；区分规则触发和检测触发。 |
| 6 独立可理解 | OS 结束后按原规则处理。 | 标出适用条件和引用对象不明确；先澄清，不自行发明。 |
| 7 一个编号一个规则 | 胶囊显示 4.5 秒，点击打开弹窗，关闭后不提醒。 | 拆成独立编号；不擅自更改时长或关闭语义。 |
| 8 表达形式 | OS 弹窗→客户端胶囊，另有 9 种检测结果组合。 | 变化可用对比；结果组合用 Markdown 表格；不强制所有内容卡片化。 |
| 9 范围控制 | 只优化 4.3 的措辞，不改变规则。 | 仅局部改写 4.3，不增补 4.5 或验收项。 |
| 10 现有行为待验证 | 我没见过更新检测失败时的 Toast。 | 标记待验证；不虚构文案、队列、合并或延迟策略。 |
| 11 原型与规则 | 原型已显示弹窗按钮位置，要求写页面说明。 | 简要描述必要组件及交互，不复述完整业务流程。 |
| 12 版本衔接 | 二期客户端自动提醒改为胶囊通知，OS 弹窗不变。 | 明确仅提醒形式变化；不推断客户端不再主动提醒。 |
