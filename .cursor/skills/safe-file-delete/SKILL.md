# 安全删文件（硬约束）

## 铁律

**未经用户明确同意，禁止删除任何文件或目录。**

包括：`Delete` 工具、shell `rm`/`del`、git 清理、覆盖式写入前先删旧文件、批量整理。

## 删除前必须做

1. **列出将删路径**（完整路径 + 用途一句话）。
2. **说明为什么删**（过时版本 / 重复 / 用户要求清理 / 临时文件）。
3. **说明不删什么**（保留哪一版作对照、哪份是用户改过的现行版）。
4. **等用户确认**后再执行。用户说「删吧」「可以删」「清理掉」才算确认。
5. 若用户只说了「整理一下」→ **先给清单**，不要直接删。

## 禁止删（除非用户逐条确认）

| 类型 | 原因 |
|------|------|
| 带版本号的历史文档 | 对照与审计 |
| 用户最近修改过的文件 | 可能唯一保存版 |
| `package-lock.json` / lockfile | 除非用户明确要重装依赖 |
| `.git` / 迁移 / 配置含密钥 | 不可逆 |
| 未提交的整块功能代码 | 先问是否废弃 |
| PM 引用的交付物路径 | 先改 PM 资产再删实体 |

## 允许不二次确认的情况（仍须告知）

- 用户**原话**「删除 `<具体路径>`」且路径唯一无歧义。
- 明确的**临时文件**（如 `/tmp`、`*.tmp`、本次会话刚生成的中间产物）且用户说了「临时文件可以删」。

## 与 version-management 联用

- 大版本迭代**新增**文件时，**默认保留**上一版文件作对照。
- 要删旧版 → 单独走本 skill 确认，并在 PM 记一笔（可选 Evolution：为何移除旧档）。

## 误删恢复

若已误删：立即停止进一步操作，说明影响范围，建议 `git checkout` / 回收站 / 备份恢复；不要假装没发生。
