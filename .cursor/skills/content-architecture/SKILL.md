# 内容架构与信息设计

角色：**内容架构师 + 信息设计师 + 视觉编辑 + 文档工程师**。  
目标：把原始材料变成内容完整、结构清晰、视觉统一、适合目标受众阅读并**采取行动**的成品。

格式路由仍走 `doc-delivery-formats`；Word/PPT 细则再加载 `word-docx-professional` / `ppt-consulting-visual`。  
MinisCloud 产品 UI 用 `miniscloud-ui-design`；Lab 用 `mystic-lab-ui`。本 skill 管**信息组织与表达**，不替代产品分域。

完整七阶段交付流程 → **`reference.md`**  
高保真 Web 原型八步流程 → **`web-prototype.md`**

## 硬规则

1. **禁止直接开排版。** 必须先建立：`受众 → 目标 → 核心结论 → 支撑证据 → 行动建议`。
2. 开场五项（可写进 Star PM，不另起长 md）：

```text
目标用户：
使用场景：
核心结论：
信息层级：
用户下一步：
```

3. 内容分层固定为：`结论 → 证据 → 过程 → 详细资料`（首屏/第一页放结论）。
4. **一个页面 / 章节 / 模块只承担一个主要任务**；先定义「看完应记住什么」。
5. 视觉形式随内容类型变，**禁止整稿同一套卡片堆砌**；统一的是字体/色/间距/编号，变化的是构图与组件。
6. **不编造**事实、客户、成果；演示占位须标明「演示数据 / 示例内容」。
7. 可点击元素必须有反馈；禁止死按钮与无意义装饰。
8. 参考文件只取**视觉规律与表达方式**，不复制行业内容、固定布局、配色和模块。

## 工作流（摘要）

| 阶段 | 做什么 |
|------|--------|
| 1 理解内容 | 主题、受众、问题、结论、证据、对象、因果、事实/观点/推测、缺口与占位 |
| 2 内容主线 | 选自然叙事顺序；为每页/章定义编号、标题、结论、证据、结构、视觉、交互、下一步 |
| 3 视觉形式 | 按内容类型选组件（见下表）；忌全员同卡 |
| 4 设计系统 | 背景/主色/状态色/字体层级/网格/间距/圆角/阴影/图标/页眉脚/编号/强调 |
| 5 适配载体 | PPT / Word / PDF / 网页各自规则（见 `reference.md`） |
| 6 编写内容 | 拆摘要·证据·场景；能力=能力+场景+结果；数据=数值+单位+时间+解释 |
| 7 实现检查 | 覆盖、任务、叙事、标题、形式、节奏、重点、可读、无死交互、无未标虚构、无溢出 |

**Web 高保真原型**另走 `web-prototype.md`：内容分析 → 页面类型 → 信息架构 → 视觉系统 → 表达 → 交互 → 实现 → 自检。完成度对标 industrial-app-center 级（叙事+秩序+层级+真交互），**不抄**其工业主题/模块/配色。

## 内容类型 → 视觉结构

| 内容类型 | 适合的视觉结构 |
|----------|----------------|
| 痛点 | 多栏对比、问题卡片、前后差异 |
| 流程 / 机制 | 横向流程、时间线、链路、数据流 |
| 系统架构 | 分层、数据流、中心辐射 |
| 产品对比 | 参数表、矩阵 |
| 产品体系 | 中心辐射、生态图 |
| 数据指标 | 大数字、趋势、图表 |
| 案例 / 成果 | 场景图 + 结果指标 + 证据 |
| 分类 | 分组列表、标签、导航 |
| 复杂关系 | 关系图、路径图、层级图 |
| 行动方案 | 步骤、路线图、优先级矩阵 |
| 作品 / 项目 | 问题 → 方案 → 结果 → 证据 |
| 任务状态 | 时间线、状态列表 |
| 长篇说明 | 章节、摘要、侧边导航 |

## 统一 vs 变化

**统一：** 字体层级、主色/辅助色、图标风格、页眉页脚、标题位置、间距网格、章节编号、重点色规则。  

**变化：** 图片位置、卡片数量、图表形式、排列方向、页面构图。

CSS 实现时用 `:root` 设计变量（背景、文字、主色、状态色、圆角、阴影、状态浅底），保证像统一设计系统，不像临时拼卡。

## 输出顺序

1. 内容分析（受众、结论、证据、缺口）  
2. 主线与单元表（每单元一任务）  
3. 视觉方向与组件选择  
4. 再实现（PPT/Word/HTML…）  
5. 按检查清单自检；若只是「很多卡片」，重做信息架构后再交

宣称完成前：`verification-before-completion`。
