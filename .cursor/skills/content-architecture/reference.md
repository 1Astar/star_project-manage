# 内容架构 · 七阶段交付（文档 / PPT / PDF / 网页）

与 `SKILL.md` 配套。动手排版前必须完成阶段 1–2。

---

## 第一阶段：理解内容

从材料提取：

1. 核心主题  
2. 目标受众  
3. 用户当前的问题  
4. 材料中的核心结论  
5. 关键事实、数据和证据  
6. 主要对象（产品、人物、流程、设备、能力、案例、数据、服务、问题等）  
7. 内容之间的因果关系  
8. 事实 vs 观点 vs 推测  
9. 缺失信息与演示占位（须标明）

建立映射：

```text
受众 → 目标 → 核心结论 → 支撑证据 → 行动建议
```

---

## 第二阶段：建立内容主线

按材料选最自然的叙事（勿强套）：

- 背景 → 问题 → 原因 → 方案 → 证据 → 行动  
- 用户 → 场景 → 痛点 → 产品 → 价值 → 转化  
- 现状 → 差距 → 机会 → 路线 → 结果  
- 产品体系 → 核心能力 → 工作流程 → 应用案例  
- 项目目标 → 执行过程 → 关键结果 → 复盘总结  
- 事实 → 分析 → 判断 → 建议  

为每一页 / 章节 / 网页模块定义：

| 字段 | 说明 |
|------|------|
| 编号 | 章节或页码逻辑 |
| 标题 | 直接说明主题或观点 |
| 本单元核心结论 | 一句 |
| 用户需理解的内容 | 要点 |
| 使用的证据 | 事实/数据/案例 |
| 推荐内容结构 | 列表/对比/流程… |
| 推荐视觉形式 | 见 SKILL 对照表 |
| 是否需要交互 | 是/否及类型 |
| 看完后的下一步 | 翻页 / 决定 / 操作 |

**一页一事。** 避免互不相关内容堆在同一单元。

---

## 第三阶段：选择视觉表达

| 类型 | 组件 |
|------|------|
| 问题痛点 | 对比卡片、问题分组、前后差异 |
| 流程机制 | 时间线、流程链路、数据流 |
| 产品架构 | 分层图、模块关系、中心辐射 |
| 参数规格 | 可读表格、指标矩阵 |
| 数据趋势 | 图表、趋势线、分布图 |
| 案例成果 | 场景图、结果指标、证据说明 |
| 分类内容 | 分组列表、标签体系、导航 |
| 复杂关系 | 关系图、路径图、层级图 |
| 行动计划 | 阶段路线、任务清单、优先级矩阵 |
| 人物经历 | 时间线、项目卡片、能力地图 |

卡片、表格、流程、时间线、图片、图表、文字各司其职；**禁止整稿同一卡片布局**。

---

## 第四阶段：建立设计系统

定义：

- 页面背景  
- 主色与辅助色  
- 状态色  
- 标题字体与正文字体  
- 标题 / 正文 / 注释字号层级  
- 页面网格与间距系统  
- 圆角系统  
- 边框与阴影  
- 图标风格、图片风格  
- 页眉页脚  
- 章节编号方式  
- 重点信息强调方式  

须满足：

- 内容不同布局可变；风格统一不散乱  
- 重点明确，不能全文同级突出  
- 信息丰富，不靠缩小字号塞内容  
- 颜色服务信息层级；装饰必须有作用  
- 不用无支撑口号；不用无意义渐变/标签/按钮装饰  

### CSS 变量示例方向（按项目改色，勿照搬工业主题）

```css
:root {
  --bg: …;
  --text: …;
  --text-muted: …;
  --primary: …;      /* 品牌 / 平台 */
  --success: …;      /* 正常 */
  --warning: …;      /* 注意 / 算力 / 告警 */
  --danger: …;       /* 风险 */
  --card: …;
  --card-emphasis: …; /* 深色重点卡 */
  --radius: …;
  --shadow-sm: …;
  --shadow-md: …;
  --bg-success-soft: …;
  --bg-warning-soft: …;
  --bg-danger-soft: …;
}
```

常见分工：深色卡承载重点；白卡承载数据；主色表平台/品牌；绿=正常；红=风险；橙=告警。色数克制：1 主色 + 2–4 辅助。

## 第五阶段：适配目标载体

### PPT

- 每页一个主要结论；标题即观点  
- 图表表格流程保持可编辑  
- 页间有叙事推进；控制密度  
- 标题 / 图形 / 正文层级分明  
- **禁止**把 Word 段落直接贴上幻灯片  

### Word

- 章节、标题、摘要、正文、表格、重点说明建阅读层级  
- 章首写清本章要解决的问题；长文拆小节  
- 复杂信息用表 / 流程 / 重点框  
- 目录、页眉页脚、页码；连续阅读体验  

### PDF

- 固定版式；处理分页、页眉脚、章节过渡、表格跨页  
- 导出后文字图片表格不溢出  
- 兼顾打印与屏幕  

### 网页

- 首屏、分区、卡片、详情层、交互入口  
- 响应式；可逐层探索  
- 重要信息优先，次要进详情层  
- 可点击元素须有真实反馈  

---

## 第六阶段：编写内容

优化表达：

- 长段落 → 摘要、重点、证据、说明  
- 抽象概念 → 具体场景  
- 能力 → 能力 + 使用场景 + 产生结果  
- 项目 → 问题 + 方案 + 执行 + 结果  
- 数据 → 数值 + 单位 + 时间范围 + 解释  
- 产品 → 目标用户 + 核心问题 + 解决方式 + 使用结果  

避免：空泛口号、无上下文大数字、重复、空标题、术语堆砌、编造事实、演示伪装成真实数据。

数字尽量交代：统计对象、时间、来源/口径、如何理解。

---

## 第七阶段：实现与检查

1. 是否覆盖原材料核心信息  
2. 每页/章是否有明确任务  
3. 叙事是否自然  
4. 标题是否直接说明内容  
5. 视觉是否匹配内容类型  
6. 页间是否有节奏变化  
7. 重点是否突出  
8. 正文是否可读  
9. 表/图/流程是否清晰  
10. 有无死按钮或无意义交互  
11. 有无未标记虚构数据  
12. 有无溢出、重叠、分页异常  
13. 是否满足载体可编辑性与使用场景  

若成品只是「很多卡片堆在一起」→ **继续重组**内容与布局，直到像经过产品思考的完整成品。

### 流水线一览

```text
原始材料
  → 提取事实与观点
  → 明确受众和目标
  → 建立内容主线
  → 拆分内容单元
  → 为每单元选择视觉形式
  → 建立统一设计系统
  → 适配 PPT / Word / PDF / 网页
  → 渲染检查并修改
```
