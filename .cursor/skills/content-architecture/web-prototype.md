# 内容驱动 · 高保真 Web 原型

完成度对标：`industrial-app-center.html` 一类——有产品叙事、丰富有序内容、清晰信息层级、统一视觉系统、真实可操作交互。  
**参考设计原则，不复制**其工业主题、页面模块、配色或固定布局。

默认技术栈（未特别说明时）：单文件 **HTML + CSS + JS**，无构建工具，可直接浏览器打开。也可按用户指定用 React / Vue / Next.js。

与文档七阶段并行：本文件专管 **Web 原型八步**。

---

## 第一步：内容分析（先于写代码）

明确：

1. 这是什么产品 / 项目 / 平台 / 主题？  
2. 主要用户是谁？  
3. 用户来到页面最想完成什么？  
4. 页面要帮用户理解 / 比较 / 操作 / 决策什么？  
5. 核心对象（产品、人物、任务、数据、服务、案例、文章、作品、能力、设备、流程等）  
6. 信息属于哪类：核心结论 / 关键指标 / 状态 / 分类 / 详细说明 / 操作入口 / 证据案例  
7. 哪些是真实提供的？  
8. 哪些缺失？用合理演示占位，并标「演示数据」或「示例内容」，**不伪装成真实事实**  

建立：

```text
用户目标 → 内容层级 → 页面结构 → 视觉表现 → 交互方式
```

---

## 第二步：自动选择页面类型

勿强套固定模板。可单选或混合：

| 形态 | 适合 |
|------|------|
| 数据驾驶舱 | 指标、运行状态、监控、企业管理 |
| 产品介绍页 | 价值、功能、案例、转化 |
| 应用中心 | 应用、能力、技能、服务入口 |
| 工作台 | 任务、流程、筛选、表格、执行 |
| 内容阅读页 | 文章、知识库、报告、长文本 |
| 作品集 | 项目经历、案例、能力证明 |
| 时间线 | 历史、进展、事件、成长 |
| 市场/商城 | 分类、商品、方案、价格、购买 |
| 个人主页 | 人物、经历、作品、联系 |
| 陪伴/生活方式 | 关系、状态、场景、情绪 |

须说明：为何适合、主线是什么、突出什么、什么进详情层。

---

## 第三步：信息架构

每个模块回答一个明确问题；不为填充而加模块。4–8 个主模块为宜，职责不重复。

每模块定义：名称、用户想知道什么、用哪些内容、内容层级、是否交互、点击后发生什么、与其他模块关系。

可采用（按需裁剪）：

1. **首屏核心表达** — 标题、定位、结论、主行动  
2. **核心价值** — 最先要理解的价值或判断  
3. **关键内容** — 指标、对象、能力、作品、服务、任务、案例  
4. **运行过程** — 工作流、时间线、数据流、关系、状态  
5. **深入查看** — 详情、分类、筛选、对比、报告、证据  
6. **行动入口** — 启用、购买、查看、联系、打开、加入、继续  

---

## 第四步：视觉系统

考虑：行业、用户身份、内容情绪、场景、信息密度、品牌气质、转化目标。

设计变量：

- 页面 / 卡片背景  
- 主文字 / 辅助文字  
- 主色、辅助色、状态色  
- 字体层级、间距、圆角、阴影、边框  
- 图标风格、动画节奏、数据展示方式  

规则：

- 1 主色 + 2–4 辅助；重要内容更高对比  
- 状态色含义明确  
- 大模块 / 小模块 / 标签 / 数字 / 说明层级分明  
- 留白、分组、对齐、重复建秩序  
- 信息丰富但不同时争注意力  
- 不为「高级感」加无意义渐变、动画、装饰  
- 不同内容类型用不同组件；风格服务内容  

风格示例（按内容选，勿固定工业风）：  
驾驶舱可用深色重点卡与状态；作品集用叙事与案例卡；阅读页用编辑排版；商城用分类与比较。

`:root` 完整变量示例见 `reference.md` 第四阶段。

---

## 第五步：内容表达

- 长段 → 摘要、重点、证据、详情  
- 复杂信息 → 分组、步骤、时间线、关系链  
- 能力 → 能力 + 适用场景 + 结果  
- 项目 → 问题 + 方案 + 过程 + 结果  
- 数据 → 数值 + 单位 + 时间 + 解释；靠近其说明  
- 状态 → 标签、进度、趋势、告警  
- 功能 → 用户动作 + 使用场景  
- 抽象 → 可视化结构  

避免：无意义大数字、空标题卡、信息重复、无上下文图表、虚构数据未标、空泛「赋能/闭环/生态/智能化」。

---

## 第六步：交互

交互服务理解、探索或完成任务。可选：标签筛选、页签、时间线筛选、详情抽屉、模态、搜索、排序、对比、展开收起、悬浮提示、图表点击、状态切换、进度、应用打开、收藏/我的列表、下一步。

- 看起来可点 → 必须有反馈  
- 禁止无功能按钮  
- 详情层比主页更深：摘要、说明、场景、过程、相关数据、操作、下一步建议  

---

## 第七步：实现要求

- 语义清晰；CSS 统一设计变量  
- JS **数据驱动渲染**；内容数据与页面结构分离  
- 勿把全部文案硬编码在复杂 DOM  
- 组件/函数职责清楚；演示数据集中管理  
- 不重复定义相同状态、事件、详情逻辑  
- 命名清楚；避免同名 CSS 冲突  
- 保持原始内容准确；缺失用演示标记  
- 桌面 + 移动；空态 / 加载 / 异常 / 无结果  
- 无文字溢出、死按钮、横向滚动  

---

## 第八步：输出与自检

**输出顺序：**

1. 内容分析（用户、目标、对象、层级、页面类型）  
2. 页面设计（IA、模块职责、视觉、交互）  
3. 内容整理（标题、摘要、指标、卡片、详情、按钮文案）  
4. 实现可运行代码  
5. 自检  

**自检清单：**

- [ ] 内容完整  
- [ ] 结构清晰  
- [ ] 无无意义模块  
- [ ] 有视觉重点  
- [ ] 内容密度足够  
- [ ] 各层级明显  
- [ ] 交互有反馈  
- [ ] 无死按钮  
- [ ] 移动端正常  
- [ ] 虚构内容已标记  
- [ ] 无布局溢出  
- [ ] 主要模块可被理解  

若只是「几张卡片拼一起」→ 继续优化 IA、表达与层级，直到具备完整产品原型感。
